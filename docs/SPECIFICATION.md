# AWG Hop — спецификация

**Версия:** 0.2  
**Дата:** 2026-05-04  
**Стек:** Go (backend), Svelte (web UI), Docker.

Название продукта: **AWG Hop** — админ-панель для входного AmneziaWG и маршрутизации трафика через исходящие AWG-туннели («hop»).

## 1. Цель продукта

Веб-админка для управления **входным VPN на базе AmneziaWG** с функциональностью, сопоставимой по UX с [wg-easy](https://github.com/wg-easy/wg-easy), и расширениями:

- **Только режим AmneziaWG для входа:** пользовательские клиенты подключаются по протоколу AmneziaWG; выдаваемые профили — **AmneziaWG-конфигурации** (совместимые с официальными клиентами AmneziaWG / рекомендованными приложениями). Отдельного «чистого» WireGuard-сервера как точки входа **нет**.
- Учёт и подъём **нескольких исходящих туннелей** к удалённым серверам (далее — **исходящие AWG-туннели**) на том же хосте.
- Для **каждого входного пира** — выбор исхода трафика после декапсуляции: **прямой выход в интернет** или **выход через выбранный исходящий AWG-туннель**.
- К **одному исходящему AWG-туннелю** можно привязать **любое количество** входных пиров.
- При **первичной установке** — опциональный **импорт данных из wg-easy** (актуально для сборок wg-easy с поддержкой AmneziaWG; см. §5.5).
- Резервное копирование и восстановление состояния.

Развёртывание по умолчанию: **Docker**, сетевые интерфейсы и правила маршрутизации изолированы **внутри сетевого namespace контейнера** (на хосте — проброс UDP/HTTPS и т.д.).

### 1.1 Принятое решение (v0.2)

Весь **входящий** VPN-traffic обслуживается стеком **AmneziaWG** (модуль ядра `amneziawg` и/или `amneziawg-tools`, см. [документацию AmneziaWG](https://docs.amnezia.org/documentation/amnezia-wg)). Это исключает режим «только стандартный WireGuard» для подключения клиентов к AWG Hop.

## 2. Термины

| Термин | Значение |
|--------|----------|
| **Вход AmneziaWG** | Серверная сторона: один логический интерфейс (имя задаётся конфигурацией), UDP-порт, на котором принимаются подключения клиентов по AmneziaWG. Управление — через API/утилиты AmneziaWG (не через классический `wg` для режима vanilla-WG на этом интерфейсе). |
| **Пир входа / входной клиент** | Удалённое устройство пользователя; в БД — запись с ключами и параметрами egress. Конфиг для пользователя экспортируется в формате **AmneziaWG** (`[Interface]` / `[Peer]` + при необходимости поля Jc, Jmin, Jmax, S1–S4, H1–H4 и т.д. по согласованию с сервером). |
| **Исходящий AWG-туннель** | Исходящий туннель от контейнера к **удалённому** AWG/WG-серверу; отдельный сетевой интерфейс. Используется как «выход в интернет через удалённый узел», а не как способ подключения пользователей к данной админке. |
| **Egress (исход)** | Куда уходит трафик входного пира после декапсуляции на входном интерфейсе AmneziaWG: `direct` (NAT в интернет контейнера) или через выбранный **исходящий AWG-туннель**. |

## 3. Сценарии использования

1. **Вход → интернет:** у пира не задан исходящий AWG-туннель; трафик маршрутизируется как у типичного VPN-сервера (forwarding + NAT наружу контейнера).
2. **Вход → исходящий AWG → удалённый сервер:** у пира указан исходящий туннель `K`; трафик с **source = VPN-адрес этого пира** уходит в интерфейс исходящего AWG `K`.

Детализация объёма трафика (полный туннель vs split) — см. раздел 6.3.

## 4. Архитектура системы

### 4.1 Компоненты

- **Backend (Go):** HTTP API (REST, при необходимости WebSocket для live-статистики), бизнес-логика, применение конфигурации к ядру/userspace AmneziaWG, управление файлами состояния, импорт/экспорт, бэкапы.
- **Frontend (Svelte):** SPA админ-панель (списки, формы, QR, графики, мастер первого запуска).
- **Хранилище:** реляционная **SQLite** (один файл в volume) с миграциями; секреты — в том же volume.
- **Один сетевой namespace:** один контейнер, внутри — **входной интерфейс AmneziaWG** и **несколько исходящих** интерфейсов (имена задаются конфигурацией).

### 4.2 Docker

- Образ: Go-бинарник, статика Svelte, **`amneziawg-tools`** (и при необходимости DKMS/модуль — политика образа: предсобранный модуль под базовый образ или документированная сборка).
- Утилиты: `iproute2`, `nftables`/`iptables` при необходимости.
- **Capabilities:** минимум `NET_ADMIN`; при userspace — `/dev/net/tun`.
- **Sysctl:** `net.ipv4.ip_forward=1` (и IPv6 при поддержке).
- **Порты:** публикация UDP порта **входа AmneziaWG**; UDP для исходящих туннелей при необходимости; HTTP(S) админки — за reverse proxy в продакшене.
- **Volumes:** SQLite, ключи, кэш экспортированных конфигов.

## 5. Функциональные требования

### 5.1 Вход AmneziaWG (аналог возможностей wg-easy по UX)

- Создание / редактирование / удаление **пиров входа**.
- Включение и отключение пира (`disabled` без удаления записи).
- Список пиров: имя, адрес в туннеле, статус, handshake, байты (через интерфейс статуса AmneziaWG, аналог `wg show` для совместимого стека).
- Выгрузка конфигурации клиента: **только AmneziaWG** (`.conf`), включая параметры обфускации, **согласованные с сервером** (серверные Jc/H/… копируются или задаются политикой, как в [wg-easy AmneziaWG](https://wg-easy.github.io/wg-easy/v15.2/advanced/config/amnezia/)).
- QR-код для данной конфигурации.
- Статистика подключения (handshake, rx/tx; при возможности — графики).
- Настройки **входного** сервера: публичный endpoint, порт, подсеть туннеля, DNS, MTU, **параметры AmneziaWG на стороне сервера** (те поля, которые должны совпадать с клиентом по правилам AmneziaWG).

### 5.2 Исходящие AWG-туннели

- CRUD для записей исходящего туннеля: имя, конфиг или поля сборки, вкл/выкл.
- Подъём/остановка при сохранении или по «Apply».
- Статус (handshake, ошибки apply).
- MVP: один поддерживаемый способ запуска и формата (уточняется при реализации образа).

### 5.3 Связь пир входа ↔ исходящий туннель (egress)

- У каждого пира поле исхода: `direct` | `awg:<id>` (идентификатор записи исходящего AWG-туннеля).
  - `direct` — NAT в «интернет» контейнера без использования исходящего AWG-туннеля.
  - `awg:<id>` — policy routing с **source = VPN-адрес пира** через интерфейс исходящего туннеля `id`.
- Несколько пиров на один и тот же исходящий туннель — обязательная поддерживаемая конфигурация.

### 5.4 Резервное копирование

- Экспорт архива: БД, ключи, текстовые конфиги, метаданные версии схемы и приложения.
- Импорт с проверкой целостности и режимами восстановления.

### 5.5 Первичная установка и импорт wg-easy

- Мастер: язык, учётная запись админа, **параметры входного AmneziaWG-сервера**, вопрос об импорте из wg-easy.
- Импорт имеет смысл для развёртываний wg-easy с **включённым AmneziaWG** (см. переменные окружения и документацию версии wg-easy). Импорт «чистого» только-vanilla wg-easy без AmneziaWG **не является целью** v0.2: при обнаружении неподдерживаемого формата — понятное сообщение и отказ с откатом.

Ссылки: [wg-easy Getting Started](https://wg-easy.github.io/wg-easy/latest), раздел AmneziaWG в wg-easy.

### 5.6 Безопасность админки

- Аутентификация администратора, HTTPS через reverse proxy в эталонном compose.
- CSRF-защита, rate limit на логин.

## 6. Сеть и маршрутизация (Linux в контейнере)

### 6.1 Идентификация трафика пира

Источником после входа в туннель является **внутренний адрес пира** в подсети входного интерфейса (например `10.8.0.5/32`).

### 6.2 Policy routing

Для пира с `egress = awg:K`: правило `from <client_vpn_ip>/32` → таблица с default через интерфейс исходящего туннеля `K`. Для `direct` — детерминированный main/`rt_direct` без конфликтов.

### 6.3 NAT и фильтрация

- MASQUERADE/SNAT по необходимости на соответствующем исходящем интерфейсе.
- MVP: ориентир на полный туннель (`0.0.0.0/0`, при поддержке — `::/0`).

### 6.4 Согласованность при изменениях

Пересчёт `ip rule`/таблиц при смене egress или отключении исходящего туннеля. Политика при недоступности туннеля — настраиваемая (по умолчанию: не применять конфиг с битой ссылкой).

### 6.5 IPv6

Явно заявить в релизе: поддерживается или IPv4-only в v0.1 MVP.

## 7. Модель данных (логическая)

### 7.1 Сущности

**IngressServerSettings** — endpoint, UDP-порт, подсеть, DNS, MTU, **поля AmneziaWG сервера** (общие для всех пиров входа, согласно выбранной модели: например Jc/Jmin/Jmax и обязательные S/H для синхронизации с клиентским конфигом).

**IngressPeer** (внутреннее имя; в API может отображаться как `peers`)

- `id`, `name`, ключи, внутренний адрес, опционально PSK.
- `enabled`.
- `egress_type`: `direct` | `egress_awg`.
- `egress_tunnel_id`: nullable FK → **EgressTunnel.id**.
- timestamps.

**EgressTunnel** (исходящий AWG-туннель)

- `id`, `name`, `interface_name` (уникально).
- Конфигурация (blob или нормализованные поля).
- `enabled`.

### 7.2 Инварианты

- `egress_type = egress_awg` ⇒ задан существующий включённый исходящий туннель.
- Много **IngressPeer** могут ссылаться на один **EgressTunnel**.

## 8. API (черновик REST)

Префикс `/api/v1`. Аутентификация обязательна, кроме health и bootstrap.

Именование путей допускает сохранение **`/wg/peers`** как синонима «пиры входа AmneziaWG» или переход на **`/ingress/peers`** — выбрать один стиль в OpenAPI.

| Метод | Путь | Назначение |
|--------|------|------------|
| GET | `/health` | Liveness/readiness. |
| POST | `/auth/login` | Логин. |
| POST | `/auth/logout` | Выход. |
| GET | `/settings/ingress` | Настройки входного AmneziaWG. |
| PUT | `/settings/ingress` | Обновление. |
| GET | `/peers` | Список пиров входа. |
| POST | `/peers` | Создать. |
| GET | `/peers/:id` | Детали. |
| PATCH | `/peers/:id` | Обновить (в т.ч. egress). |
| DELETE | `/peers/:id` | Удалить. |
| GET | `/peers/:id/config` | Текст `.conf` **AmneziaWG**. |
| GET | `/peers/:id/qrcode` | PNG/SVG QR. |
| POST | `/peers/:id/enable` | Включить. |
| POST | `/peers/:id/disable` | Выключить. |
| GET | `/egress-tunnels` | Исходящие туннели. |
| POST | `/egress-tunnels` | Создать. |
| GET | `/egress-tunnels/:id` | Детали + статус. |
| PATCH | `/egress-tunnels/:id` | Обновить. |
| DELETE | `/egress-tunnels/:id` | Удалить (проверка ссылок от пиров). |
| POST | `/system/apply` | Применить сеть. |
| GET | `/system/status` | Сводка интерфейсов и ошибок. |
| POST | `/backup/export` | Скачать архив. |
| POST | `/backup/import` | Загрузить архив. |
| POST | `/setup/wg-easy-import` | Импорт из каталога wg-easy (AmneziaWG). |

## 9. Web UI (Svelte) — экраны

1. Логин.  
2. Dashboard: пиры входа, handshake, исходящие туннели.  
3. **Пиры входа (AmneziaWG):** таблица, CRUD, вкл/выкл, скачать конфиг, QR.  
4. Форма пира: ключи/генерация, **egress:** Интернет или список исходящих AWG-туннелей.  
5. **Исходящие AWG-туннели:** список, редактор конфига, статус.  
6. **Настройки входного сервера** AmneziaWG (включая параметры обфускации сервера).  
7. Бэкап.  
8. Мастер первого запуска.  
9. Импорт wg-easy (при поддерживаемом режиме).

## 11. Риски и открытые вопросы

1. **Версии amneziawg / amneziawg-tools:** поведение полей и обратная совместимость — зафиксировать поддерживаемые версии в README образа.
